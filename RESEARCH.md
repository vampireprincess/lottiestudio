# Downloading technology review (30 September 2026)

This review informed Framekeeper's implementation. **A maintained extractor is not a guarantee that every public post works**: websites change per region, account and date. The browser and helper each validate URLs, and the helper reports extractor errors instead of silently falling back to fragile/unauthorized site scraping.

## Alternatives evaluated

| Approach | Advantages | Why it was not chosen as the sole engine |
| --- | --- | --- |
| **yt-dlp Python API + FFmpeg (chosen)** | Maintained multi-platform extractors, metadata, format selection, progress hooks, cookie reading, HLS/DASH handling, and local merging. We install its recommended `curl-cffi` extra for browser/TLS impersonation, which may be needed on TikTok. Recent official releases actively changed TikTok and Instagram. [1](https://github.com/yt-dlp/yt-dlp/releases/tag/2026.08.19) [5](https://github.com/yt-dlp/yt-dlp/) | Individual failures remain possible even with impersonation; regular updates required. FFmpeg is a separate local prerequisite. |
| **Browser-only MV3, `chrome.downloads`, content scripts** | No native app installation for a simple direct MP4 URL. Content scripts can read DOM metadata in an isolated world. [1](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts) | DOM/video `src` may be a short-lived signed CDN URL or blob, and separate audio/video or HLS/DASH require more than a direct file download. Building three site-specific extractors would be brittle; Chrome's MV3 worker is event-driven. A maintained MV3+companion project explicitly notes signed URLs expiring. [2](https://github.com/Relatoxin/media-downloader) |
| **Platform-specific DOM/GraphQL extensions** | An open-source MV3 social-media extension demonstrates Instagram Reels/carousel harvesting and in-browser media processing. [5](https://github.com/th3sull1van/social-media-downloader) | Its Facebook module focuses on photo content; writing/maintaining separate TikTok, Instagram and Facebook site parsers is out of scope. [5](https://github.com/th3sull1van/social-media-downloader) |
| **Existing native-messaging browser extension patterns** | A Chrome extension can delegate yt-dlp to Python; Chrome starts the host on demand and an active native port keeps the service worker alive. [1](https://github.com/opalsaints/yt-dlp-chrome-extension) [1](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) [3](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) | Requires one-time host registration tied to the unpacked extension ID. The cited example targets YouTube/macOS, so we implement our own small cross-platform bridge, not copy its downloader logic. |
| **Local HTTP helper** | Simple to prototype and independent of Chrome's native host registration. A 2026 MV3+Windows companion demonstrates loopback communication. [2](https://github.com/Relatoxin/media-downloader) | Must keep a server running, secure local HTTP against other websites/processes, and poll for progress across popup/service-worker lifecycle. Native messaging avoids a listening port and sends progress immediately. |
| **Instaloader** | Active Instagram-specific project; **v4.15.3** released July 2026 with post metadata fixes. [3](https://github.com/instaloader/instaloader/releases) | Good potential future Instagram-only fallback, but doesn't provide a uniform TikTok/Facebook quality/progress interface. More dependencies and code paths for a small personal app. |
| **gallery-dl** | Actively maintained for galleries and social media; **v1.32.14** appeared September 2026 (development moved to Codeberg). [1](https://github.com/mikf/gallery-dl/releases/tag/v1.32.14) | Strong for bulk images/carousels, less focused than yt-dlp on this app's *single-video quality + audio conversion* workflow. Optional future carousel support. |
| **Cobalt (self-host)** | Open-source API documents TikTok, Instagram and public Facebook capabilities. [2](https://github.com/imputnet/cobalt/blob/main/api/README.md) | It says no public pre-hosted API is available; self-hosting needs another service/container and adds setup. Facebook is public-only, and metadata varies by platform. No paid API is used here. [2](https://github.com/imputnet/cobalt/blob/main/api/README.md) [4](https://github.com/imputnet/cobalt/blob/main/docs/run-an-instance.md) |

## Architecture decision & boundaries

Use **Chrome MV3 popup + isolated content script + event-driven service worker + on-demand Python native host**. Chrome's native messaging documentation specifies a per-user manifest with an exact `allowed_origins` extension ID; it launches the host and uses length-prefixed messages. The service-worker lifecycle documentation says `connectNative()` keeps the worker alive while the port is open. [1](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) [3](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

The helper, not the content script, resolves playable media. It accepts only supported single-video URLs and runs `yt_dlp.YoutubeDL` with a strict format selection. Browser cookie reading is **opt-in** and local to yt-dlp; it cannot bypass access controls or rescue a broken extractor. Output files go straight to a local folder, and Chrome's `storage.local` contains only settings, job progress and history (no cookies). On browser shutdown an in-flight native process may be interrupted; after restart the worker marks that job as interrupted rather than pretending it finished. Canceling can leave a `.part` file.

**Verification scope:** automated tests cover URL spoofing/path validation, host installation/framing, extension job flow, and real yt-dlp+FFmpeg download/audio conversion against an offline local media fixture. They do *not* assert that a particular third-party TikTok/Instagram/Facebook link will always work on every network/account; that would be misleading given the upstream issues above. The best response to an extractor regression is to upgrade yt-dlp and report the failing public URL upstream where appropriate.
